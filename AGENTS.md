# Sergio

Instructions for any coding agent working in this repository: Codex, Gemini
CLI, Cursor, GitHub Copilot, OpenCode, Goose, Zed, Kiro, Amp, Claude Code
(which reads them through `CLAUDE.md`), and others that read `AGENTS.md`.

This repository is two things, and a session here is usually one of them:

- **The code** of the studio: reusable media packages (`packages/`), the
  product built on them (`studio/`), and the skills its agent uses (`skills/`).
- **The studio itself**, run from the repository root: an agent produces
  narrated, illustrated videos in the library (`library/`, a link to the
  production data; never committed).

## Producing video

The studio's tools come from the `pva` MCP server
(`studio/agent/mcp/server.ts`). Each harness starts it from its own project
file: `.mcp.json` (Claude Code, VS Code), `.codex/config.toml` (Codex),
`.gemini/settings.json` (Gemini CLI), `.cursor/mcp.json` (Cursor),
`opencode.json` (OpenCode). It serves the same tools Pi gets from
`studio/agent/extensions/index.ts`, unchanged: `pva_channels`, `pva_journal`,
… (your harness may prefix them, as `mcp__pva__pva_channels`). Where the
harness supports MCP prompts, the studio's slash commands are prompts too
(`/video`, `/render`, …).

- Before production work, load the `pva-executive-producer` skill; each stage
  has its own skill (`write-brief`, `write-script`, `compose-video`, …).
  Skills are in `.agents/skills/` and `.claude/skills/` once `bun install`
  has run; `pva_list_skills` and `pva_load_skill` serve the same ones to a
  harness that reads no skills.
- A library holds channels (series of episodes) and films. A film is
  produced at three levels — film, scene, shot — each with its own cut and
  renders (ADR-0050): load `film-producer` first.
- A person may ask for a ready-made style ("in the risograph style", "using
  'Tide riso'"): load `style-templates`. A style is never required.
- Paid generation is budgeted per episode: `pva_budget_status` before spending.
- Only the operator approves a stage. Ask with `pva_request_approval`; never
  approve on their behalf.
- Operator review comments and stage updates reach you as a block headed
  "Studio activity since …", in a pva tool result or before your next prompt:
  read review activity with `pva_journal` and respond to it.
- Generated media stays in the library, never in git (ADR-0021).

Start the agent from the repository root: the server finds the library and
`tsx` from there. [docs/running.md](docs/running.md) covers each harness, the
gateway and the browser studio.

## Changing the code

Read [docs/repository-layout.md](docs/repository-layout.md) first, then
[docs/contributing.md](docs/contributing.md).

- `packages/*` never import from `studio/` (`npm run check:boundaries`).
- The agent's tools are written once, against Pi's extension API, in
  `studio/agent/src/`. Pi loads them directly; the MCP server hosts the same
  registrations for every other harness (`studio/agent/mcp/host.ts`). Do not
  fork a tool per harness.
- Skills are edited in `skills/` and `studio/agent/skills/`; `.pi/skills/`,
  `.claude/skills/` and `.agents/skills/` are generated by `npm run compose`.
- Before pushing: `npm run check`.
